# scripts/ — 这些脚本是干什么的，需要担心吗

> **一句话**：这四个脚本是本仓库**维护者自己用的发布流水线**，不是给你装的软件。
> 你 clone 这个仓库只是看文档、看插件源码，**不需要运行它们**，也**不会自动运行**。

## 四个脚本是什么

| 脚本 | 干什么 | 谁需要 |
|---|---|---|
| `audit-secrets.ps1` | 扫目录里的密钥/令牌/私钥/本机用户名，命中就**拒绝推送**（退出码 1） | 维护者。发布前的一道闸门 |
| `sanitize-copy.ps1` | 白名单式复制要发布的文件，复制的同时按规则**替换私有路径与用户名** | 维护者。把私有资产脱敏后归档 |
| `push-to-github.mjs` | 走 GitHub REST API 推送归档目录（本机没有 git 时用） | 维护者。**必须显式 `--push`**，不给参数只提示用法 |
| `verify-remote.mjs` | 推送后**从 GitHub 拉回内容**独立复扫一遍，不信任本地状态 | 维护者。防止本地查过、线上仍有残留 |

**特点：三个是「查」，一个是「推」。没有「删」和「装」。**

## 会不会被安全中心当成病毒/木马/后门

**风险主要来自四个「像坏东西」的特征，逐个说明：**

### ① PowerShell 脚本（`.ps1`）

杀毒软件对 `.ps1` 的误报率确实偏高，因为 PowerShell 常被恶意软件当"无文件攻击"的载体。
但这两个脚本里**没有**恶意软件常用的动作：

```
❌ 没有 Invoke-Expression / iex           （不执行动态字符串）
❌ 没有 DownloadString / IWR             （不联网下载再执行）
❌ 没有 Set-ExecutionPolicy 改动          （不改系统策略）
❌ 没有 base64 解码执行                    （不藏载荷）
❌ 没有 reg add / schtasks                 （不改注册表、不建计划任务）
❌ 没有 Remove-Item -Recurse 大面积删除    （不删你的东西）
```

它们只做：读文件、做正则匹配、复制文件、创建归档目录。

### ② Node 脚本（`.mjs`）

`push-to-github.mjs` 会联网——但只连 `api.github.com`，且需要你提供 token。
`verify-remote.mjs` 只读不写。

**可疑度低**：正规的 HTTP 客户端 + 公开 API，行为模式像 `gh` 命令行。

### ③ 读环境变量里的 token

```js
process.env.GH_TOKEN
```

`push-to-github.mjs` 会读 `GH_TOKEN` 或 PowerShell 用户环境变量。
**这是唯一"敏感"的行为**——但和 `gh`、`git push` 是同一级别的正常操作。
脚本**不会**把 token 写进任何文件或发往别处（`audit-secrets.ps1` 反而在查这个）。

### ④ 自动扫描整个目录

`audit-secrets.ps1` 默认扫"脚本所在目录的上一级"，`sanitize-copy.ps1` 也有一套候选根目录。

**看起来像"到处翻文件"**，这正是杀软会警觉的模式。
但：**只在显式运行时做，不常驻、不自启、没有定时任务。**

## 如果你要跑（一般不需要）

```powershell
# 先看它想推什么，不写任何东西
node scripts/push-to-github.mjs --dry-run
```

```powershell
# 只想检查有没有密钥泄露
pwsh -File scripts/audit-secrets.ps1 -Target .
```

**两个都是"只读"或"只打印"，可以放心先跑。**

## 结论

```
需要这些脚本吗？
  → 你是维护者：需要（它们是发布流水线）
  → 你只是 clone 来看的：不需要，别运行，也不要担心

会被当病毒吗？
  → 个别杀软可能对 .ps1 报警（行业普遍现象）
  → 行为上没有任何恶意动作；报警属于「按扩展名猜」的启发式误判
  → 想彻底避免：只 clone 不运行，或者用 GitHub 网页看源码
```

## 万一杀软拦了怎么办

1. **先别急着加白名单**——自己去 GitHub 网页上把脚本读完（每个都不到 15 KB）
2. 确认没做过的事：不删文件、不改注册表、不建计划任务、不下载执行
3. 如果只是要文档/插件，**根本不用跑脚本**，直接跳过
4. 实在要跑，建议在**虚拟机或容器**里跑一遍看行为

## 补充：CLI 的 `Secret Scanning`

本仓库开启了 GitHub 的 secret scanning（`.gitleaks.toml` + Actions 工作流），
每次 push 会自动扫一遍。**这也是为什么这套脚本存在**——
与其等平台报警，不如提交前自己先拦下来。
